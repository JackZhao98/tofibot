# TOFI v0.6.0

Changes since v0.2.1.

## Computer is optional

- A Bot works without a computer. You can install TOFI on a host without KVM.
- An admin can attach or detach an account's computer while TOFI runs. Detach asks first, waits for the current step, and copies the files to the server.
- The admin sets the size of each computer. Members can see the size but not change it.
- Each computer has a lock. It is given to one Bot at a time for each tool call.

## Local connections and security

- Local connections, such as Gmail, run in a separate tool runner container. They keep working when a computer is attached or detached.
- Each account's tools run in their own network, with process limits, memory limits and a disk quota.
- Tool processes run without privileges and with a system-call filter.
- The runner container is fenced off from the host and the local network. TOFI refuses to start it if the fence cannot be set up. The host needs `iptables`.
- Pairing other devices is off in this release.

## Bots and settings

- A Bot can read and change settings for you: its own profile, other Bots, your preferences, conversations and connections.
- Changes to another Bot, to permissions or to connections show a confirmation card first. Other changes show a notice with Undo.
- Scheduled and other unattended runs can read settings but cannot change them.
- A Bot can look up the product manual and send you a link that opens the right Settings page.
- Bot looks and the theme are stored on the server, so they follow you to other devices.
- When a Bot calls an outside tool, a schedule counts as a standing request of the Bot it targets.

## Settings and chat

- Settings has a new layout. Pages that few people use are in a folded Advanced group.
- Permissions is one control: Auto or Ask. Search & fetch and Behavior are separate pages.
- Each model provider has its own card. A Claude key starts with a smaller, faster default model.
- The activity of a run is one timeline in time order.
- Retry on a failed run shows "Retrying..." until the server starts the new run. A refusal shows its reason.
- The sidebar shows the new calico logo.

## Updates and data

- An admin can update from the web page. The server waits for running Bots, backs up, and rolls back if the new version fails.
- An update starts the tool runner container and waits until it is healthy. If it does not start, the update rolls back.
- `tofi status` shows the runner. `tofi update --check` says when an update adds it.
- On a server updated from v0.2.1, this update adds the tool runner container.
- If an update rolls back with "worker container stopped uncleanly", run it again. The rollback keeps all data.
- TOFI refuses to start on a database that a newer version wrote, and tells you how to update or restore.
- A model without a known context window now assumes 500,000 tokens.
