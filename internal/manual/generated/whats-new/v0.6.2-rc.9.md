# TOFI v0.6.2-rc.9

## Local models

- A server Admin can now connect Ollama or another model server on the local network. Before, a standard install refused every private address, even for the only account. Members still need the operator to allow it.
- `TOFI_ALLOW_PRIVATE_ENDPOINTS=1` in `/etc/tofi/tofi.env` now reaches the App. It allows private addresses for every account, for models and MCP servers. Metadata and link-local addresses are never allowed.

## First direct message

- The first message asks one question: what you want help with.
- Four tasks you can hand over right away show under it. A click fills the message box; nothing is sent until you send it.
- If your first message is a single task, the Bot does it and keeps a general role and a personal name.

## Home Assistant

- Connect Home Assistant from Connections with its address and a long-lived access token. Bots can read states and control devices. Every change asks for your approval first.

## Monthly spend limit

- Settings › Usage has a monthly limit in whole dollars, off by default. At 80% you get one notice. At 100%, every call to a billed model is refused, including background calls.
- ChatGPT and Codex sign-ins, local models and models without a known price are not counted.
- Admins see each account's spend this month.

## Installer

- New access option: through a VPN (Tailscale). The port still listens on all interfaces; close TCP 8321 at the firewall.
- The installer prints how long it took. Without KVM it names the clouds that offer nested virtualization.
- `tofi doctor` lists exposure checks: public bind, an unused setup key, plain-HTTP sign-in on a public address, a published MCP Runner port.

## Fixes

- An MCP server saved by a member can no longer reach private or metadata addresses, including through OAuth discovery.
- A Bot no longer repeats a question card as a chat message.
