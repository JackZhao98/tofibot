## C1 设计记录（owner 2026-10-23，进行中）

把真人团队里的协作拆成一个工作流状态机。底层模型：

1. **等待 = 异步调用。** 等 Bot 回话、等命令、等人、等时间，本质都是“发出调用，结果晚点到”。异步调用马上返回回执，结果作为事件送回。现有三套（`follow_up`/`run_waits`、委派回传、B1 最后完成者回传）收编为一套。
2. **可以同时挂多个等待，也可以编组“全部到齐再处理”。** 等的过程中 Bot 可以先跟用户说一句，然后继续等。
3. **所有进来的事件同一规则：先挂起，不打断。** 用户新消息、子 Bot 结果、命令结束、超时，都先进收件箱（已送达、未读）。当前这一个工具调用结束后，Bot 读到新事件，带着它继续干。**之前的进度不能丢**（现状是取消 run、新 run 只拿到摘要，要改）。
4. **等待的意识。** 每轮上下文列出在等什么、等多久、何时超时；Bot 能取消。`outcome=pending` 只有存在真实等待才算数。
5. **超时也是结果。** 到点把“超时”送回给 Bot 决定；等待落库，重启不丢；界面可见、可取消。
6. **派出去的子 Bot 归派活的 Bot 掌管。** 派活的 Bot 能随时给子 Bot 插话（和用户给主 Bot 插话同一机制）、能叫停、能看进度；子 Bot 收到新要求后调整做法或停下。用户改需求时，主 Bot 必须能把改动传给已派出的子 Bot。
