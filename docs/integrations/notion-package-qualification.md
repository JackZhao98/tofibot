## Narrow compatibility fix

Vendor options default to stdio, process repeated `--transport <value>` in order, and use separate gateway authentication for HTTP mode. HTTP startup source also issues an identity request to Notion. Vendor proxy source gives `OPENAPI_MCP_HEADERS` priority over `NOTION_TOKEN`; `BASE_URL` changes the API destination. These options conflict with the private-token/default-destination stdio profile already claimed by the candidate.

Only the opted-in Notion profile now rejects non-stdio, missing or conflicting transport options and either reserved override in `Env` or `SecretEnv`, before secret-file reads or child creation. The equals-form transport check is conservative: the examined vendor parser does not recognize that dialect. Generic configurations remain unchanged. The runner already uses an explicit child environment rather than inheriting the host environment. No command bytes or package attestation are implied by this guard.

Synthetic baseline tests accepted eight invalid transport cases and four reserved override cases. After the fix, five new focused test functions and two existing protocol/private-token functions passed in `0.404s`. Tests verify rejection before reading an intentionally missing synthetic token file, zero child methods, accepted stdio controls, generic-config preservation, exact protocol negotiation and private token modes. No full-suite repeat or live-provider acceptance was performed in this follow-up. The new fix still needs independent review.
