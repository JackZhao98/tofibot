# TOFI v0.6.0

Changes since v0.2.1.

## Computer is optional

- A Bot works without a computer. You can install TOFI on a host without KVM.
- An admin can attach or detach an account's computer while TOFI runs. Detach asks first, waits for the current step, and copies the files to the server.
- The admin sets the size of each computer. Members can see the size but not change it.
- Each computer has a lock. It is given to one Bot at a time for each tool call.

## Bots and settings

- A remark sent while a Bot works no longer replaces the work: the Bot answers it and finishes the original request; if it does not, the request is paused and resumed.
- Only the resumed run works on a paused task, so the same work is not done twice.
- Every change a Bot makes to a Bot profile is recorded with Undo, and a Bot reports a change as made only after the change succeeded.
- New setting: pages a Bot may fetch in one run (default 20).
- Work that a new message interrupts, or that a Bot stops before it is done, is paused on the Bot's task list for the conversation. When the current work ends, the Bot resumes it and says which task it resumes, however often it was interrupted. A task the Bot keeps stopping by itself is restarted at most twice and stays on the list. "Paused" tasks show Resume and Drop.
- Bots use connected tools (MCP, Gmail, Calendar) first and use the computer only when no connected tool fits, a tool fails, or you ask for the computer.
- Bots find TOFI's own tools (schedules, work items, settings) by search, and can pause or delete their schedules in any conversation.
- A Bot can read and change settings for you: its own profile, other Bots, your preferences, conversations and connections.
- Changes to another Bot, to permissions or to connections show a confirmation card first. Other changes show a notice with Undo.
- Scheduled and other unattended runs can read settings but cannot change them.
- A Bot can look up the product manual and send you a link that opens the right Settings page.
- Bot looks and the theme are stored on the server, so they follow you to other devices.

## Computer

- Right after Attach, the size sliders load once the computer is ready instead of showing an error.
- After an admin detaches their own computer, the Computer card (with Attach) stays on their page and on every member's page. The card shows one status line, a quiet Detach, and the size sliders as rows.
- The Admin console can attach and detach an account's computer. Detach asks first, waits for the current step, and copies the files to the server.
- A Bot works without a computer. An admin can attach or detach the computer while TOFI runs.
- The admin sets the size of each computer. Members can see the size but not change it.
- Computers have a lock per computer, given to one Bot at a time for each tool call.

## Security

- `tofi security audit` no longer reports the runner key file path as a secret.
- The tool runner has its own AppArmor profile and cgroup namespace, so the per-account memory and process limits apply. `tofi security` checks them.
- Each account network can resolve names again (the DNS forwarder could not bind its port).
- The tool runner does not start without its network fence. `tofi security` checks the fence.
- Each account's tools run in their own network, process limits, memory limits and disk quota.
- Tool processes run without privileges and with a system-call filter.

## Updates and data

- Two uploads at the same moment on a new account no longer fail.
- The update waits through a short unhealthy state of the tool runner on slow hosts, and a rollback brings the App back even when the runner does not start.
- An update fails and rolls back if the tool runner does not start. `tofi status` shows the runner.
- Local connections keep working when an admin attaches or detaches a computer.
- If an update from v0.2.1 rolls back with "worker container stopped uncleanly", run it again. The old Worker sometimes cannot confirm its computer cleanup; the rollback keeps all data.
- TOFI refuses to start on a database that a newer version wrote, and tells you how to update or restore.
- A model without a known context window now assumes 500,000 tokens.

## Interface

- The browser tab icon has a lagoon-green tile so it stays visible on light tab bars.
- Sidebar previews show plain text. A finished task no longer shows "Paused". An undone change cannot be undone twice.
- Disconnecting Gmail shows a clean "Not connected" state; an expired authorization shows "Reconnect". Each Google service has its own Enable API link.
- Reactions on your own message stay under it. The live status is not repeated on wide screens.
- Models is now AI Models. OpenAI is one card: sign in with ChatGPT or use an API key. A saved key shows only its first and last characters; Replace and Remove are secondary actions.
- Dictation appears only when OpenAI is connected (the Claude API has no transcription model).
- Permissions sets the approval mode for the account (Auto, Ask before edits, Per Bot), lists every Bot with its own mode, and picks the auto review model.
- Maintenance has a Check for updates button.
- A Bot's own check of its reply against the sources shows as a quiet step, not as a failure. Copy diagnostics is removed.
- Scheduled task actions are one row of icon buttons.
- The browser tab icon is the calico cat. Pinned tiles show a press state.
- Other devices is hidden until the desktop client exists.
- The Settings navigation keeps a thin scrollbar and does not squeeze its labels.
- The working dot on a pinned tile sits inside the tile.
