# TOFI v0.6.2

Changes since v0.6.1. Tofi is in early beta: read these notes before you update, and keep backups (`tofi update` makes one first).

## Start without a cloud account

- New model provider: any OpenAI-compatible server, such as Ollama, LM Studio, vLLM or OpenRouter. Ollama needs no key; the card reads its model list and context size.
- First-run setup can connect Ollama or your own server. A server Admin can use an address on the local network. For other accounts, the operator sets `TOFI_ALLOW_PRIVATE_ENDPOINTS=1` in `/etc/tofi/tofi.env`. Metadata and link-local addresses are never allowed.
- Measured: install on a 2 vCPU, 2 GiB host without KVM in 39 s; first reply from `qwen2.5:7b` on an Apple M2 in 89 s, later replies in 4–10 s. Small models chat well but use tools less reliably.
- OpenAI models can use OpenAI's own web search when no other search source is set.

## Bots split work and hand parts to the crew

- When a request has independent parts, the Bot you asked can lead: it gives each part to a group member whose role fits (or to its own sub-runs), runs them in parallel, checks the results and gives one answer. This also works when you @mention only that Bot.
- One plan card follows the assignment message: each part is a checklist item with its owner, deadline and state. Each member's result folds into its item.
- If the lead stops with an error, the parts keep going. If you stop the lead, its parts stop too. Limits: 4 parts at once, 2 levels deep, deadlines of 30 minutes (60 in scheduled runs). Settings > Behavior has all four.

## Work trace

- At the end of a run that used the Bot computer, a folded "Work trace" line shows the steps as pictures. It also shows under the reply when Activity is hidden.
- No picture is stored while a secret is typed, during a takeover, or on websites in your private list. Settings > Behavior turns it off and sets how many days to keep pictures (default 7).
- Screenshots can be taken at overview size for state checks, and a Bot can stitch its screenshots into one image to check its work.

## First direct message

- The first message asks one question: what you want help with.
- Four tasks you can hand over right away show under it. A click fills the message box; nothing is sent until you send it. With a model that was not evaluated (a local model, for example), the list says to check that the task was really done.
- If your first message is a single task, the Bot does it and keeps a general role and a personal name.
- An empty Bot chat offers three templates: Morning briefing, Inbox digest and Watch a web page.

## Home Assistant

- Connect Home Assistant from Connections with its address and a long-lived access token. Bots can read states and control devices. Every change asks for your approval first. This is new; tell us how it works with your setup.

## Monthly spend limit

- Settings > Usage has a monthly limit in whole dollars, off by default. You get one notice when spend passes 80% or reaches the limit. At the limit, every call to a billed model is refused, including background calls, and the task says why.
- ChatGPT and Codex sign-ins, local models and models without a known price are not counted. Admins see each account's spend this month.

## Tools a Bot can recover from

- A tool error names the problem: the missing field and the values it takes, the unexpected field, the wrong type. Large external (MCP) tool schemas reach the Bot with their top-level fields first.
- Long results say what was left out and how to get the rest. Files, web pages, skills, attachments, chat history, schedules and work items can be paged.
- Web search and page reading say which sources were tried and why one was skipped. Web search can filter by date range and website.
- The browser retries a slow page or lost connection, lists open tabs when none is in focus, and tells the Bot to check the result of an action whose effect is unknown.
- Google: save Gmail attachments, read and export Drive files, create Calendar events (reviewed like other writes). Email drafts support Cc, Bcc and replies in a thread.

## Bot computer

- "Bot computer" is the name everywhere for the computer a Bot uses. Today's kind is the built-in virtual machine.
- A hibernated Bot computer gives back its CPU and memory when another account needs to start one. After an update it stays hibernated until it is used, then starts on the new release.

## Install and security

- New install path: Docker Compose for a server without KVM. Add the Bot computer later with `sudo tofi computer add kvm`.
- New access option in the installer: through a VPN (Tailscale). The port still listens on all interfaces; close TCP 8321 at your firewall.
- The installer prints how long it took and, without KVM, which clouds offer nested virtualization.
- `tofi doctor` lists exposure checks: a public bind, an unused setup key, plain-HTTP sign-in on a public address and a published MCP Runner port.
- An MCP server saved by a member can no longer reach private or metadata addresses, including through OAuth discovery.
- The installer can send an anonymous install report. It is off by default, also with `--yes`.

## Fixes

- A reaction menu no longer closes at once when the chat list settles by a pixel.
- A Bot no longer repeats a question card as a chat message.
- Replies that used OpenAI's web search no longer show raw citation codes.
- In a group, a Bot that leaves a note for another Bot now shows a collapsed "Left a note" row.
- After an admin saves an account's storage limit, "Saved." stays on screen.

## Update

```sh
sudo tofi update
```

Or press Update in Settings > Maintenance > Version. An update from v0.6.1 keeps Bots, conversations, attachments, accounts and settings; it backs up first and rolls back if the new version fails.
